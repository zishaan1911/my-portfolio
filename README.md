information, in a design inspired by old terminals.

## Live data

`src/data/repos.json` and `src/data/updates.json` are generated by
`scripts/sync.mjs` and committed to the repo, so the page needs no API call at
runtime and crawlers see real content. `.github/workflows/sync.yml` refreshes
them twice a day and pushes straight to `main`.

```bash
npm run sync      # needs GITHUB_TOKEN (optional) and GROQ_API_KEY (optional)
```

Without `GROQ_API_KEY` the script still runs and simply keeps GitHub's own repo
descriptions.

### Setup

1. **Enable Actions.** Scheduled workflows are *disabled by default in forked
   repositories*. Open the Actions tab and enable them, or the cron never fires.
2. Add a repository secret `GROQ_API_KEY` from https://console.groq.com/keys.
3. Nothing else — `GITHUB_TOKEN` is provided automatically.

### The guard

An LLM writing project descriptions unsupervised will eventually invent a
number: "improved performance" becomes "improved performance by 40%", and that
ends up on a portfolio being defended in an interview.

So nothing generated is trusted. `scripts/guard.mjs` checks every candidate
against the README it came from and rejects it if it:

- contains a figure that doesn't appear in the source
- uses unsupported hype ("state-of-the-art", "production-ready", superlatives)
- reads as model chatter ("Sure! Here's...", "As an AI...")
- is too long, too short, or contains a link

A rejected description falls back to the repo's own GitHub description. The
same rules apply to every line of the updates feed.

**Known limitation, stated plainly:** the check catches digits, not numbers
spelled as words. "Three developers" would pass where "3 developers" would not.
The prompt asks for digits and the banned-phrase list covers the common cases,
but this is a net, not a wall. Skim the diffs.

`npm test` covers the guard and runs a mocked end-to-end sync. CI runs both
*before* generating anything — if the guard is broken, nothing is written.

### Cost

Descriptions are cached against a hash of each README, so Groq is only called
when a README actually changes. A quiet week costs nothing. The model is
`openai/gpt-oss-20b`; note that `llama-3.1-8b-instant` and
`llama-3.3-70b-versatile` were **decommissioned on 2026-08-16**, so most
tutorials you'll find name a dead model.

## Blog

The blog tab is hidden from the nav because I have no posts yet. To enable it:

1. Add posts to `src/example/blog.xml` (the structure is commented in the file).
2. Restore this line to the `<nav id="nav-tabs">` list in `index.html`:
   ```html
   <li><a id="blog-tab" class="tab-switcher" href="#blog">Blog</a></li>
   ```

The `<div id="blog">` container is deliberately left in the DOM even while
hidden — `routing.js` calls `getElementById('blog')` unconditionally and would
throw on every navigation without it.

## Running locally

It's static, but the JS uses ES modules, so it needs to be served over HTTP
rather than opened as a `file://` URL:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```
